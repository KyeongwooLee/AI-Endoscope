**3. 수정 효과**

**3-1. 유형마다 다시 뽑기가 얼마나 통하나**

- 수정 효과는 유형 라벨에 안 쓴 별도 샘플(T=0.7)로 계산함.
- 1.5B로 다시 풀게 했고, 3B는 참고용.


| 유형       | 1번 다시 | 다수결 5 | 다수결 15  | (참고) 3B |
| -------- | ----- | ----- | ------- | ------- |
| B 주로 맞힘  | 76%   | 86%   | **96%** | 97%     |
| C 막힘     | 3%    | 1%    | **4%**  | 27%     |
| D 두 답 경쟁 | 33%   | 40%   | 51%     | 76%     |
| E 답이 여럿  | 33%   | 42%   | 55%     | 67%     |


- B는 다수결로 거의 다 고쳐짐.
- C는 아무리 다시 뽑아도 안 고쳐짐. 같은 오답이 반복되니 다수결이 오히려 그 오답을 굳힘.
- D·E는 절반 정도 고쳐짐.
- 그래서 "유형마다 필요한 수정이 다르다"는 건 확인됨.

**3-2. 다수결 대신 hidden으로 답 고르기 (probe vote)**

- 여러 답마다 hidden probe로 "틀렸을 확률"을 계산하고, (1 − 틀릴 확률)을 표 무게로 준 다수결.
- 답은 greedy 1개 + T=0.7 샘플 4개(K=5).


| 방법 (K=5)                   | B       | C   | D       | E       | 전체 정답률    |
| -------------------------- | ------- | --- | ------- | ------- | --------- |
| 다수결                        | 78%     | 3%  | 26%     | 30%     | 88.1%     |
| 확신도 가중 다수결                 | 82%     | 4%  | 29%     | 34%     | 88.0%     |
| **probe vote (hidden 가중)** | **87%** | 3%  | **39%** | **39%** | **89.1%** |


- probe vote 예시:

모델이 낸 답 5개(greedy 1개 + 샘플 4개)가 이렇습니다.


| 답                 | 20  | 20  | 20  | 18  | 18  |
| ----------------- | --- | --- | --- | --- | --- |
| probe가 본 "틀렸을 확률" | 0.8 | 0.8 | 0.8 | 0.1 | 0.1 |
| 표 무게 (1 − 틀릴 확률)  | 0.2 | 0.2 | 0.2 | 0.9 | 0.9 |


**다수결**: 20이 3표, 18이 2표라서 20을 고릅니다. 틀렸습니다.

**probe vote**: 같은 답끼리 무게를 더합니다.

- 20 = 0.2 + 0.2 + 0.2 = 0.6
- 18 = 0.9 + 0.9 = 1.8

그래서 18을 고르고, 맞혔습니다.

즉 "많이 나온 답"이 아니라 "모델 속(hidden)이 덜 불안해한 답"에 표를 더 주는 방식입니다. 정답이 소수로 섞여 나오는 D·E 유형에서 효과가 큰 이유가 이겁니다.

- probe vote가 다수결보다 전체 정답률이 +1.0%p 높음 [+0.6, +1.3]. K=3에서도 +1.3%p.
- 정답이 소수로 섞여 나오는 D·E에서 특히 +9~13%p 더 고침. 다수결은 소수 정답을 못 고르지만, hidden은 그 정답을 알아봄.
- C는 어떤 고르기로도 안 고쳐짐. 5개 중 정답이 있는 경우부터 28%뿐이라 고를 대상이 없음. C에는 다시 뽑기가 아닌 다른 수정법이 필요함.

**3-3. 1단계 탐지와 합친 결과**


| 방법                              | 정답률       | 비용 (1.5B 1회 = 1) |
| ------------------------------- | --------- | ---------------- |
| greedy만                         | 82.3%     | 1.0              |
| 탐지 상위 25% → 다수결 (5개)            | 86.5%     | 2.0              |
| **탐지 상위 25% → probe vote (5개)** | **87.3%** | 2.0              |
| 탐지 상위 40% → 다수결 (5개)            | 87.6%     | 2.6              |
| **탐지 상위 40% → probe vote (5개)** | **88.5%** | 2.6              |
| 탐지 상위 25% → 다수결 15 (새 샘플)       | 88.9%     | 4.75             |
| 탐지 상위 40% → 다수결 15 (새 샘플)       | 90.5%     | 7.0              |


- 같은 비용이면 probe vote가 다수결보다 정답률이 0.8~0.9%p 높음.
- 이 구조에서는 hidden을 두 번 씀. 한 번은 고칠 문제를 고를 때(탐지), 또 한 번은 답을 고를 때(probe vote).
- 수정 대상을 고를 때도, 같은 비용에서 hidden으로 탐지하면 확신도로 탐지할 때보다 정답률이 1%p 정도 높음. 이 비교는 T=1 샘플로 함.
- 다수결 15 행은 3-1의 새 샘플 15개를 쓴 거라 비용이 더 큼. probe vote를 15개 답에 적용하는 건 그 답들의 hidden을 추출해야 해서 아직 못 함.

**3-4. test 셋 확인 (처음 보는 문제)**

- 지금까지는 train 안에서 교차검증한 결과. 처음 보는 문제에서도 되는지 GSM8K test 1,319문제로 확인함.
- probe는 train 답 37,365개(7,409문제 × 5개)로 한 번만 학습하고, test에는 그대로 적용만 함.
- test greedy 정답률은 72.0%.


| 비교 (test)             | 기존    | 바꾼 후  | 차이     | 95% 신뢰구간       |
| --------------------- | ----- | ----- | ------ | -------------- |
| 다수결 → probe vote, K=3 | 73.8% | 76.3% | +2.4%p | +1.1 ~ +3.8    |
| 다수결 → probe vote, K=5 | 76.9% | 78.2% | +1.4%p | +0.1 ~ +2.4    |
| 다수결 → 확신도 가중, K=5     | –     | –     | −0.7%p | 0 포함 (유의하지 않음) |



| 방법                              | train 정답률 | test 정답률  | 비용  |
| ------------------------------- | --------- | --------- | --- |
| greedy만                         | 82.3%     | 72.0%     | 1.0 |
| 탐지 상위 25% → 다수결 (5개)            | 86.5%     | 74.9%     | 2.0 |
| **탐지 상위 25% → probe vote (5개)** | **87.3%** | **76.2%** | 2.0 |
| 탐지 상위 40% → 다수결 (5개)            | 87.6%     | 76.0%     | 2.6 |
| **탐지 상위 40% → probe vote (5개)** | **88.5%** | **77.3%** | 2.6 |


- train에서 본 결과가 test에서도 그대로 유지됨. probe vote 이득은 오히려 조금 더 큼.
- 확신도 가중은 test에서도 이득이 없음. hidden이어서 생긴 효과라는 게 다시 확인됨.
- K=5는 신뢰구간 하한이 +0.1이라 아슬아슬함. K=3 결과가 더 확실함.
- 탐지 AUROC의 train 값은 3-2와 같은 답별 probe 기준이라 1번 표(0.865)와 조금 다름.
- test 정답률(72%)이 train(82%)보다 많이 낮음. train 문제가 사전학습 데이터에 섞였을 가능성이 있음.
